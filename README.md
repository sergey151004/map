# Карта и метки

Одно учебное приложение для трёх последовательных заданий из `tasks/`.
Выполнено задание 1: карта, навигация и фотографии меток.
Долгое нажатие на карту создаёт метку, обычное нажатие открывает её ID и координаты.
Для каждой метки можно выбрать фото из галереи, увидеть миниатюры и удалить отдельное фото.
Метки и фотографии хранятся в React Context и сохраняются при переходах между экранами.
После перезапуска приложения они сбрасываются. SQLite, геолокация
и уведомления будут добавляться на следующих этапах.

## Установка и запуск

Требуются Node.js LTS, npm и Expo Go с поддержкой SDK 57.
Версию Expo Go можно проверить на https://expo.dev/go.

```powershell
cd D:\coding\map_project
npm ci
npm start
```

Зависимости уже установлены при подготовке. `npm ci` нужен после скачивания проекта
или для повторной установки точных версий из `package-lock.json`.
Команда `npm start` выполняет `expo start --go`.
В `.npmrc` кеш npm направлен в `.npm-cache/` внутри проекта, поскольку при подготовке
на системном диске C: не хватило места. Эта папка исключена из Git и проверки TypeScript.

Если Expo CLI сообщает `ENOSPC` из-за заполненного C:, в текущем PowerShell можно
перенаправить его служебную папку на D: перед запуском:

```powershell
$env:__UNSAFE_EXPO_HOME_DIRECTORY = 'D:\coding\map_project\.expo-cache'
npm start
```

Это временный обход для данной машины; новая служебная папка не использует сохранённый
в прежней папке вход в аккаунт Expo. `.expo-cache/` исключена из Git.

1. Установите Expo Go на телефон и подключите телефон и компьютер к одной сети Wi-Fi.
2. Отсканируйте QR-код из терминала: на Android — сканером в Expo Go, на iPhone — камерой.
3. Дождитесь карты (начальная область — Екатеринбург).
4. Двумя долгими нажатиями в разных местах добавьте две метки.
5. Откройте первую метку: проверьте числовой ID, широту и долготу.
6. Нажмите «Вернуться к карте», откройте вторую метку и вернитесь кнопкой назад в заголовке.
7. Убедитесь, что обе метки остались на карте, а счётчик показывает 2.
8. Откройте первую метку: видны координаты и сообщение «Фотографий пока нет».
9. Нажмите «Добавить изображение», выберите фото. Повторите для второго фото:
   должны появиться две миниатюры с числовыми ID.
10. Вернитесь на карту и откройте вторую метку: её список должен быть пустым.
    Добавьте ей другое фото. Вернитесь к первой: её две фотографии должны остаться.
11. Удалите одно фото первой метки: второе остаётся, фото другой метки не меняется.
    Удалите последнее фото первой метки: снова появляется пустое состояние.
12. Откройте галерею и отмените выбор: список не меняется, кнопка снова доступна.
13. Несколько раз быстро нажмите кнопку добавления: открывается один picker,
    после выбора появляется только одна новая запись. Добавьте несколько фото и проверьте прокрутку.

Проверка ошибок: ограничение полного доступа к фотографиям в настройках телефона
не должно мешать системному выбору отдельного фото. В этом режиме диалог разрешений
обычно не появляется. Если система возвращает ошибку разрешений, приложение показывает
сообщение о доступе; другие ошибки picker — сообщение о невозможности открыть галерею
или прочитать фото. Для воспроизводимой проверки ветки ошибки в разработке можно временно
заменить вызов picker на `throw Object.assign(new Error(), { code: 'ERR_USER_REJECTED_PERMISSIONS' })`,
а для общей ошибки — на `throw new Error()`. После проверки восстановите вызов.
Чтобы проверить ошибку миниатюры, временно передайте в `addImage` несуществующий
`file:///missing-test-photo.jpg`: вместо изображения появится сообщение, удаление останется доступным.
Перезапуск приложения очищает метки и фотографии — на этом этапе это ожидаемо.

Дополнительно откройте ссылки `exp://<адрес Metro>/--/marker/abc` и
`exp://<адрес Metro>/--/marker/999999` на телефоне: должны появиться сообщения
«Некорректный ID метки» и «Метка не найдена» с возможностью вернуться на карту.

Если локальная сеть блокирует соединение, разрешите Node.js доступ к частной сети
в брандмауэре Windows или запустите туннель:

```powershell
npx expo start --go --tunnel
```

При первом запуске туннеля Expo может предложить установить `@expo/ngrok`.
Для уже настроенного Android-эмулятора можно использовать `npm run android`.
iOS-симулятор требует macOS; на Windows используйте физический iPhone с Expo Go.

Результат экспорта находится в игнорируемой папке `dist/`.

При подготовке успешно выполнены проверка TypeScript, `expo install --check`,
чтение конфигурации, все 21 проверки Expo Doctor и экспорт Hermes для Android и iOS.
Команда `npm start` проверена: Metro запустился в режиме Expo Go; пробный сервер остановлен.
Проверка на физическом телефоне или эмуляторе в этой среде недоступна.

После добавления карты повторно прошли TypeScript, проверка совместимости зависимостей,

(в том числе отсутствующий параметр, массив, дробь, отрицательное и слишком большое число).

проверить на телефоне по сценарию выше: устройство и эмулятор здесь недоступны.

## Структура

- `app/_layout.tsx` — стек навигации, заголовки и общий `MarkersProvider`.
- `app/index.tsx` — карта, добавление меток и переход на экран деталей.
- `app/marker/[id].tsx` — проверка ID, координаты, выбор фотографий и возврат к карте.
- `components/ImageList.tsx` — миниатюры, ошибки отображения, удаление и пустой список.
- `contexts/MarkersContext.tsx` — метки и изображения в памяти, последовательные числовые ID.
- `types.ts` — типы метки, изображения и параметров маршрута.
- `utils/parseMarkerId.ts` — проверка ID из URL: положительное безопасное целое число.
- `app.json` — конфигурация Expo и плагина Router.
- `tsconfig.json` — строгая проверка TypeScript на основе конфигурации Expo.
- `tasks/` — исходные задания, сохранены без изменений.

Используются функциональные компоненты и хук `useLocalSearchParams`.
Context расположен над навигатором, поэтому переходы не сбрасывают список меток.
Проект настроен для Android и iOS; демонстрационных вкладок и экранов шаблона нет.

Зависимости Expo подбираются через `npx expo install`, а не через установку
произвольных `latest` из примеров заданий. При добавлении следующих возможностей
нужно сверяться с документацией установленного SDK: пример SQLite с
`openDatabase` / `transaction` в задании 2 устарел.

Основа проекта: Expo SDK 57, React 19.2.3, React Native 0.86.3 и Expo Router 57.
Версии React DOM, Gesture Handler, Reanimated и Worklets также закреплены по
списку совместимости Expo: они требуются дереву зависимостей Router.
Повторно подбирать их при обычной установке не нужно — используйте `npm ci`.

Команды подбора зависимостей при подготовке:

```powershell

npx expo install react-dom react-native-reanimated react-native-worklets react-native-gesture-handler
```

## Фотографии и разрешения

Используется `expo-image-picker` из SDK 57: `mediaTypes: ['images']`, без редактирования
и множественного выбора. Системный picker на поддерживаемых Android/iOS предоставляет
доступ к выбранному фото без запроса полного доступа к медиатеке. Камера и микрофон
не используются. Ограниченный или запрещённый полный доступ к галерее не является
основанием блокировать системный picker.

`canceled` обрабатывается без ошибки. Исключения открытия/чтения показываются на экране;
коды ошибок разрешений получают отдельное сообщение. `Image.onError` заменяет неудачную
миниатюру понятным текстом. Ref и отключённая кнопка защищают от повторных нажатий
во время операции, блокировка снимается в `finally`, включая отмену и ошибку.
Осознанно выбрать одно и то же фото отдельными операциями можно.

В памяти хранятся только URI, числовые ID и связь `markerId`. Удаление убирает запись
из приложения, но не удаляет оригинал из галереи. Долговременное хранение файлов пока
не реализовано; при перезапуске процесса (включая выгрузку Android во время picker)
состояние сбрасывается.

API сверено с [документацией SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/imagepicker/)
и исходниками установленного пакета.

## Загрузка карты и ограничения

Используется `react-native-maps` 1.27.2, согласованная с Expo SDK 57.
В Expo Go дополнительные ключи карт не нужны; геолокация пока не запрашивается.
Карта занимает всю доступную область основного экрана под заголовком навигации.

Индикатор отображается до `onMapReady`, также включён штатный `loadingEnabled`.
Если готовность не наступила за 15 секунд, появляется сообщение об ожидании и кнопка
повторной инициализации карты. Это тайм-аут ожидания, а не доказательство сетевой ошибки.
Повторная инициализация не удаляет метки из Context.

В API этой версии нет общего `onError` карты. `onMapReady` означает готовность
нативного компонента, но не гарантирует загрузку картографических данных.
`onMapLoaded` не поддерживается Apple Maps на iOS, поэтому ожидание не привязано к нему.
Expo Router ErrorBoundary обрабатывает ошибки рендера React с кнопкой повтора;
нативные сбои и ошибки загрузки тайлов он не перехватывает.

Справка: [react-native-maps для SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/map-view/).

Документация: [установка Expo Router](https://docs.expo.dev/router/installation/),
[Expo Router для SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/router/).
