# Карта и метки

Учебное приложение на React Native, Expo SDK 57, TypeScript и Expo Router.
Выполнено задание 1, подключена SQLite из задания 2 и добавлена геолокация при активном
приложении из задания 3. Локальные уведомления автоматически появляются при входе
в радиус 100 метров от сохранённых меток и удаляются при выходе.
Исходные задания находятся в `tasks/`.

## Установка и запуск

Требуются Node.js 24 LTS, npm и Expo Go с поддержкой SDK 57.

```powershell
cd D:\coding\map_project
npm ci
npm start
```

Подключите компьютер и телефон к одной сети Wi-Fi. Отсканируйте QR-код:
на Android — в Expo Go, на iPhone — камерой. Для Android-эмулятора есть
`npm run android`; iOS-симулятор требует macOS.
Если сеть блокирует подключение, используйте `npx expo start --go --tunnel`
(Expo может предложить установить `@expo/ngrok`).

На этой машине диск C: заполнен. Кеш npm перенаправлен в `.npm-cache/` через `.npmrc`.
Если Expo сообщает `ENOSPC`, перед запуском в текущем PowerShell выполните:

```powershell
$env:__UNSAFE_EXPO_HOME_DIRECTORY = 'D:\coding\map_project\.expo-cache'
npm start
```

Новая служебная папка Expo не использует сохранённый в прежней папке вход в аккаунт.
Кеши, `node_modules`, `.expo` и `dist` исключены из Git.

Зависимости подбирались через `npx expo install`, в том числе:

```powershell
npx expo install react-native-maps expo-image-picker expo-sqlite expo-file-system
npx expo install expo-location
npx expo install expo-notifications
```

Установлены Expo 57.0.27, SQLite 57.0.4, FileSystem 57.0.7, Location 57.0.20 и Notifications 57.0.22.
Для обычной повторной установки используйте `npm ci`, чтобы сохранить версии из lock-файла.

## Как работает приложение

- Долгое нажатие на карту добавляет маркер в SQLite.
- Нажатие на маркер открывает его числовой ID, координаты и фотографии.
- Системная галерея выбирает одну фотографию. Отмена не изменяет данные.
- Выбранный файл копируется в `Paths.document/marker-photos/` с уникальным именем.
  В SQLite сохраняется URI копии, а не временный URI галереи.
- Фотографии можно удалять по одной. Удаление маркера требует подтверждения,
  удаляет связанные записи и копии фото, затем возвращает на карту.
- Данные обновляются после операций и при возврате на экран через `useFocusEffect`.
- Загрузка, ошибка и кнопка повтора видны на экране. Ошибку можно закрыть,
  например чтобы выбрать другое фото вместо недоступного исходного файла.
- После полного закрытия и открытия приложения маркеры и фотографии сохраняются.
  Удаление приложения или очистка его данных удалит и локальные данные.

## Соединение, Context и ошибки

`DatabaseProvider` находится над навигатором в `app/_layout.tsx`.
`useDatabase()` предоставляет шесть операций задания, `markers`, `images`,
`isLoading`, `error`, обновление и повтор. Массивы в Context — кэш содержимого SQLite,
а не отдельное хранилище. Старый `MarkersContext` удалён.

`database/connection.ts` управляет одним соединением. Инициализация, операции,
синхронизация и файловая очистка выполняются последовательно. Обычная навигация
соединение не закрывает. При размонтировании провайдера закрытие ставится в очередь
после уже принятых запросов. Повторная установка эффекта в React Strict Mode также
проходит через эту очередь, не создавая два одновременно открытых соединения.

Если основной запрос уже выполнен, но чтение результата или очистка файлов не удались,
кнопка повтора выполняет только оставшиеся шаги: успешный INSERT не повторяется.
После закрытия сообщения данные перечитываются без повторения отменённой операции.
Диагностика выводится только при `__DEV__`; исходная причина ошибки сохраняется в `cause`.

## SQLite

SQL находится только в `database/`. Используются актуальные асинхронные методы
`expo-sqlite` и встроенный тип `SQLiteDatabase`, без ORM и `@types/sqlite3`.

`initDatabase()` открывает `markers.db` в постоянной папке SQLite приложения.
До транзакций включается и проверяется `PRAGMA foreign_keys = ON`.
При `PRAGMA user_version = 0` обе таблицы создаются вместе с установкой версии 1
в одной транзакции. Повторная инициализация сохраняет данные. Более новая или
некорректная версия, конфликт схемы и ошибки запросов не приводят к сбросу базы.

```sql
CREATE TABLE markers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    latitude REAL NOT NULL,
    longitude REAL NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE marker_images (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    marker_id INTEGER NOT NULL,
    uri TEXT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (marker_id) REFERENCES markers (id) ON DELETE CASCADE
);
```

Операции: `addMarker`, `deleteMarker`, `getMarkers`, `addImage`, `deleteImage`,
`getMarkerImages`; внутренний `getAllImages` нужен для синхронизации и очистки файлов.
Слой SQL принимает первым параметром соединение, а Context скрывает его от экранов.
Значения передаются через `?`. Один DELETE и его каскад атомарны в SQLite.
В результатах `marker_id` отображается в `markerId`, `created_at` — в `createdAt`;
названия столбцов в БД не меняются. `createdAt` допускает NULL, как схема задания.

## Согласованность фотографий и базы

Файловая система и SQLite не имеют общей транзакции. Поэтому используется такой порядок:

1. Создать копию фото и проверить её наличие и непустой размер.
2. Записать URI копии в БД. При ошибке записи удалить новую копию.
3. При удалении сначала выполнить SQL, затем убрать принадлежащие приложению файлы,
   которые больше не упоминаются ни в одной записи изображений.

Если SQL-удаление не удалось, файлы остаются целыми. Если очистка файла не удалась,
запись уже удалена, но остаётся копия: показывается ошибка и доступен повтор очистки.
Такая же проверка выполняется при запуске и синхронизации. Она убирает незавершённые
копии после остановки процесса между копированием и INSERT или между DELETE и очисткой.
Сканирование выполняется только после успешного чтения всех URI из БД и в той же очереди,
поэтому не удаляет файл незавершённой операции добавления.

Удаляются только файлы с нашими именами `photo-...` непосредственно в `marker-photos`.
Оригиналы галереи, другие каталоги и чужие файлы не удаляются. Неизвестные URI из старой
базы не считаются принадлежащими приложению. Произвольная очистка документов или удаление
пользователем файлов вручную всё ещё может сделать фотографию недоступной: миниатюра
покажет ошибку с возможностью повтора или удаления записи.

### Ручная проверка сохранения

1. Запустите приложение в Expo Go. Дождитесь карты и добавьте две метки долгими нажатиями.
2. Откройте первую: проверьте ID/координаты, добавьте два разных фото. Второй добавьте одно.
3. Вернитесь на карту и снова откройте обе метки. Списки фото должны быть раздельными.
4. Полностью закройте Expo Go через список приложений (на Android можно принудительно
   остановить его в настройках). Не очищайте данные приложения и не переустанавливайте его.
5. Снова откройте тот же проект через Expo Go: оба маркера и все три миниатюры должны остаться.
6. Удалите одну фотографию первой метки и повторите полное закрытие/открытие:
   удалённая фотография не возвращается, остальные остаются.
7. На первой метке нажмите «Удалить маркер», сначала отмените: всё остаётся.
   Затем подтвердите: откроется карта, первая метка исчезнет, вторая останется.
8. Перезапустите ещё раз: удалённая метка не возвращается, фото второй доступны.
9. Проверьте отмену галереи и быстрые повторные нажатия: одна операция не должна добавлять дубликаты.
10. Проверьте неверную ссылку `exp://<адрес Metro>/--/marker/abc` и несуществующий ID:
    должно быть понятное сообщение с возвратом на карту.

Схему можно дополнительно осмотреть через `PRAGMA table_info(markers)`,
`PRAGMA table_info(marker_images)`, `PRAGMA foreign_key_list(marker_images)` на том же
соединении в отладчике. `foreign_keys` и `user_version` должны быть 1,
`foreign_key_check` — пустым. После удаления маркера запрос
`SELECT * FROM marker_images WHERE marker_id = ?` для его ID должен вернуть пустой список.
Папка `Paths.document/marker-photos` должна содержать только используемые копии
после успешной очистки. Полный каскад и откат при его ошибке также проверяются тестами.

Для проверки ошибок на устройстве можно временно вызвать исключение перед копированием,
перед INSERT или перед удалением файла в соответствующем сервисе. После восстановления
кода нажмите «Повторить операцию»: не должно появиться лишней записи. После неудачного
копирования/INSERT не должно быть новой строки, после ошибки очистки — чужих удалённых файлов.

## Карта и разрешения

`react-native-maps` 1.27.2 использует `onMapReady` и `loadingEnabled`. После 15 секунд
ожидания готовности появляется повтор инициализации. Общего `onError` карта не предоставляет;
готовность не гарантирует загрузку всех тайлов. ErrorBoundary ловит ошибки рендера React,
но не нативные сбои. `onMapLoaded` не используется из-за отсутствия поддержки Apple Maps.

В Expo Go для карт не нужны дополнительные ключи. Галерея выбирает только фотографии
без редактирования: системный picker на поддерживаемых Android/iOS не требует полного
доступа к медиатеке. Камера и микрофон не используются. Отмена обрабатывается отдельно,
ошибки доступа и чтения показываются на экране. Копирование в документы приложения
не требует разрешения на общую файловую систему телефона.

## Геолокация при активном приложении

`LocationProvider` расположен в корневом layout над навигатором. Единственная подписка
управляется в `services/location.ts`; карта и детали не запускают собственные подписки.
Запрашивается только `requestForegroundPermissionsAsync` («При использовании приложения»).
Фоновые разрешения, сервисы, TaskManager и geofencing не используются; соответствующие
параметры плагина `expo-location` явно выключены.

Параметры `watchPositionAsync`: `Accuracy.Balanced`, `timeInterval: 5000`,
`distanceInterval: 5`. Временной интервал поддерживается только на Android.
Это настройки запроса, а не обещание координаты ровно каждые 5 секунд или 5 метров:
частоту и точность определяют платформа, доступность сигнала и настройки пользователя.
При Balanced и приблизительном разрешении небольшое перемещение может быть незаметно.

На карте синяя метка «Вы здесь» берёт координаты из Context. `showsUserLocation`
выключен, чтобы карта не включала дополнительное нативное отслеживание. При первой
позиции карта центрируется один раз; далее её можно свободно двигать. Кнопка
«Моё местоположение» возвращает к текущей позиции. Синяя метка не записывается в SQLite.

Пока первой координаты нет, видны ожидание и повтор. После 20 секунд текст предлагает
проверить условия приёма, но подписка продолжает ждать. Отказ, выключенная геолокация,
ошибка запуска и ошибка подписки показываются отдельными состояниями. Ошибки GPS не
блокируют карту, метки, фотографии и операции SQLite. После отказа приложение не
повторяет системный запрос автоматически при каждом возвращении: повтор разрешения
возможен по кнопке, а при `canAskAgain: false` предлагаются настройки приложения.

В активном приложении раз в 5 секунд проверяются доступность служб и разрешение
(это не дополнительная подписка на координаты). При их отключении текущая подписка
снимается, устаревшая позиция скрывается. После включения нажмите «Повторить» либо
вернитесь в приложение из настроек.

`AppState` останавливает отслеживание при любом состоянии кроме `active`, включая
`inactive`, и запускает его заново при возвращении. Удаляются подписка и таймеры;
при размонтировании удаляется также обработчик AppState. Проверка поколения запуска
игнорирует поздние callbacks, а поздно полученный дескриптор подписки сразу удаляется.
Очередь запусков не допускает пересечения старого и нового watch, включая Strict Mode.
GPS-история и координаты пользователя на диск не сохраняются.

## Уведомления при приближении

`utils/calculateDistance.ts` использует формулу Хаверсина и возвращает метры.
Радиус `PROXIMITY_THRESHOLD = 100` задан в `services/proximity.ts`: это выбор проекта,
так как задание не задаёт число. Граница включена: расстояние ≤ 100 метров считается
входом, расстояние > 100 — выходом. Дополнительного гистерезиса нет.

`ProximityProvider` расположен над навигатором внутри провайдеров базы и геолокации.
Изменение координат или списка меток запускает проверку. Менеджер хранит `Map` активных
уведомлений по `markerId` со значениями `notificationId` и `timestamp` (время в мс).
Переходы между экранами не пересоздают менеджер. В SQLite это состояние не записывается.

Перед отправкой ID метки попадает в `Set` выполняющихся отправок. Поэтому частые
координаты не создают дубли даже до получения notificationId. После успеха новые
отправки для этой метки блокируются до выхода из зоны; разные метки независимы.
При выходе или удалении метки активное состояние очищается, уведомление удаляется.
Если отправка ещё идёт, её поздний результат удаляется. Каждому входу соответствует
отдельный объект: при быстром выходе и входе старый результат не станет уведомлением
нового посещения. После его очистки разрешается одна новая отправка.

При ошибке отправки блокировка снимается: повтор возможен на следующем обновлении
координат/меток или по кнопке «Повторить уведомления». Немедленного цикла повторов нет.
Неудачные удаления сохраняются отдельно по notificationId для следующей попытки.
Ошибка видна на карте и в деталях. Отсутствие координат при фоне, отказе или ожидании
не считается выходом: состояние зоны сохраняется, новые отправки не запускаются.
Удалённые метки очищаются даже без GPS. После возвращения первая свежая позиция
определяет, остался ли пользователь в зоне. При размонтировании уведомления удаляются,
включая результаты ещё не завершённых отправок.

### Ручная проверка

1. Запустите `npm start`, откройте Expo Go и разрешите геолокацию. Для воспроизводимой
   проверки задайте в эмуляторе позицию `56.8389, 60.6057` и дождитесь её на карте.
2. Добавьте две метки рядом с синей точкой (примерно в 20–50 метрах). Разрешите
   уведомления: появится по одному «Вы рядом с меткой!» с разными ID.
3. Несколько раз измените позицию на 10–20 метров, оставаясь в радиусе обеих меток.
   Откройте детали каждой и вернитесь: новых уведомлений быть не должно.
4. Переместите позицию в `56.8439, 60.6057` (примерно 550 метров севернее).
   После новой GPS-координаты оба уведомления должны исчезнуть из центра уведомлений.
5. Вернитесь в исходную точку: должно появиться по одному новому уведомлению.
6. Удалите одну из близких меток через её детали. Должно исчезнуть только связанное
   с ней уведомление; оставшаяся метка не должна вызывать повторное.
7. Сверните приложение и вернитесь, оставаясь на месте: после получения координаты
   новых уведомлений для той же зоны быть не должно. В фоне перемещение не отслеживается.
8. Запретите уведомления Expo Go в настройках, выйдите из зоны и войдите. Появится
   сообщение об отказе; карта и фотографии работают, системный запрос не повторяется.
   Разрешите уведомления (и Android-канал «Уведомления о метках»), вернитесь и нажмите
   «Повторить уведомления» либо дождитесь следующего обновления GPS.

На телефоне повторите вход/выход прогулкой с запасом от границы 100 метров. При
`Accuracy.Balanced` GPS может колебаться около границы и создавать реальные для
алгоритма выходы/входы. Точное сравнение 100 метров и асинхронные гонки проверены тестами.

`services/notifications.ts` регистрирует общий обработчик из корневого layout.
`showMarkerNotification(markerId)` возвращает `{ ok: true, notificationId }` либо
ошибку/отказ с сообщением. `removeNotification(notificationId)` отменяет ожидающее
и удаляет уже показанное уведомление по тому же ID. Ошибки возвращаются вызывающему
коду; сам сервис повторов не запускает. Разрешение проверяется перед каждой отправкой,
но системный запрос выполняется только при неопределённом статусе, один раз за сеанс.
На Android канал с высокой важностью создаётся перед запросом разрешения.

Временная тестовая кнопка удалена: все новые уведомления проходят через менеджер зон.
После полного завершения процесса память зон сбрасывается; при новом запуске вход
считается новым. При принудительном завершении ОС не гарантирует выполнение очистки:
оставшиеся в центре старые уведомления можно удалить вручную.
Баннер и звук зависят от настроек системы, режима «Не беспокоить» и канала;
временное разрешение iOS (provisional) допускает тихое появление в центре уведомлений.

Проверки сервиса: `npm run test:notifications` (4 теста с подменой нативного API).
Проверки расстояния и менеджера: `npm run test:proximity` (9 тестов: граница 100 м,
защита от дублей, независимые метки, выход/удаление/повторный вход во время отправки,
ошибки и повтор, отсутствие GPS и размонтирование).
Реальный показ на телефоне или эмуляторе в этой среде проверить нельзя.
API и поддержка локальных уведомлений в Expo Go сверены с
[Notifications SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/notifications/).

## Основные файлы

- `app/` — карта, детали и навигация.
- `contexts/DatabaseContext.tsx` — соединение, операции, кэш и повтор ошибок.
- `contexts/LocationContext.tsx`, `services/location.ts` — состояние геолокации и жизненный цикл подписки.
- `components/LocationStatus.tsx` — ожидание, ошибки, повтор и переход к позиции.
- `services/notifications.ts` — показ и удаление локальных уведомлений.
- `utils/calculateDistance.ts`, `services/proximity.ts` — расстояние и состояние зон.
- `contexts/ProximityContext.tsx`, `components/ProximityStatus.tsx` — подключение менеджера и ошибки.
- `database/` — схема, SQL, очередь соединения и ошибки базы.
- `services/` — сохранение/очистка копий и повтор без дубликатов.
- `components/ImageList.tsx`, `components/DatabaseStatus.tsx` — фото и состояние операций.
- `types.ts`, `utils/parseMarkerId.ts` — модели и проверка ID маршрута.
- `tests/` — автоматические проверки хранилища, геолокации и уведомлений.

API сверено с установленными пакетами и документацией
[SQLite SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/sqlite/),
[FileSystem](https://docs.expo.dev/versions/latest/sdk/filesystem/),
[ImagePicker SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/imagepicker/).
