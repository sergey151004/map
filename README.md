# Карта и метки

Учебное приложение по трём заданиям из `tasks/`: карта с сохранёнными маркерами,
фотографии мест, SQLite, текущая геопозиция и локальные уведомления о приближении.
Одно приложение на React Native, Expo, TypeScript и Expo Router. Используются
функциональные компоненты, хуки и React Context; сервера, авторизации и ORM нет.

## Реализованные функции

- Карта на основном экране; долгое нажатие добавляет маркер с числовым ID.
- Нажатие на маркер открывает его ID, координаты и собственный список фотографий.
- Выбор фото из галереи, миниатюры, удаление фото и пустое состояние списка.
- Удаление маркера с подтверждением, связанными записями фото и копиями файлов.
- Постоянное хранение маркеров и фотографий между запусками приложения.
- Синяя метка текущей позиции и кнопка «Моё местоположение».
- По одному локальному уведомлению для каждой метки в радиусе 100 метров;
  выход за 150 метров завершает посещение, повторный вход разрешает новую отправку.
- Восстановление системных уведомлений после перезапуска и результата галереи после
  пересоздания Android Activity.
- Состояния загрузки, понятные ошибки, повтор неудачных операций и проверка ID маршрута.

Из новой папки:

```sh

cd map_project
npm ci
npm start
```

Для уже скачанного проекта выполните `npm ci` и `npm start` в его корне.
`npm ci` устанавливает версии из `package-lock.json`. `npm start` выполняет
`expo start --go`. При необходимости добавления нативных пакетов используйте
`npx expo install <имя-пакета>`, чтобы Expo подобрал совместимую версию.

Открытие в Expo Go:

1. Установите или обновите [Expo Go](https://expo.dev/go) до версии с SDK 58.
   Подключите телефон и компьютер к одной Wi-Fi-сети.
2. Дождитесь QR-кода в терминале после `npm start`.
3. На Android отсканируйте его через Expo Go, на iPhone — камерой и откройте ссылку в Expo Go.
4. Дождитесь загрузки проекта и разрешите местоположение при использовании приложения.
   Разрешение уведомлений запрашивается при первой попытке уведомить о близкой метке.

После перехода с SDK 57 выполните `npm ci` и первый запуск с очисткой кеша Metro:
`npm start -- --clear`. Данные приложения очищать не нужно; миграции выполняются автоматически.

## SQLite

База `markers.db` хранится в постоянном каталоге SQLite приложения. Схема соответствует
заданию 2, включая имена столбцов, `created_at` и числовые автоинкрементные ID:

```sql
CREATE TABLE markers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    latitude REAL NOT NULL,
    longitude REAL NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE marker_images (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    marker_id INTEGER NOT NULL,
    uri TEXT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (marker_id) REFERENCES markers (id) ON DELETE CASCADE
);
```

Связь «один маркер — много изображений». Удаление маркера каскадно удаляет его строки
`marker_images`; один DELETE вместе с каскадом атомарен в SQLite. Файлы очищаются отдельно.

`database/schema.ts` открывает соединение, включает и проверяет `PRAGMA foreign_keys = ON`
до транзакций. При `user_version = 0` создаёт таблицы; текущая версия БД — 3.
Миграция 1 → 2 заменяет абсолютные URI собственных фото относительными путями,
сохраняя ID, связи и даты; неизвестные URI остаются без изменений. Миграция 2 → 3
добавляет `pending_image_pick`: единственный незавершённый запрос галереи с токеном,
ID метки и URI выбранного источника. При удалении метки запрос удаляется каскадно.
Миграции и изменение
версии выполняются в одной транзакции до очистки файлов. Повторный запуск сохраняет данные.
При ошибке выполняется откат; база
автоматически не сбрасывается. Более новая версия схемы отклоняется с ошибкой.

`database/operations.ts` содержит `addMarker`, `deleteMarker`, `getMarkers`, `addImage`,
`deleteImage`, `getMarkerImages`; внутренний `getAllImages` нужен для синхронизации файлов.
Используется асинхронный API `expo-sqlite` со встроенными типами и параметрами `?`.
В JS-результатах `marker_id` называется `markerId`, а `created_at` — `createdAt`.

## Context и обработка ошибок

Все три провайдера находятся над навигацией:

- `DatabaseProvider` / `useDatabase()` предоставляет операции, кэш прочитанных данных,
  `isLoading`, `error`, обновление и повтор. Очередь управляет одним соединением;
  при размонтировании оно закрывается после принятых операций, при переходах — остаётся открытым.
- `LocationProvider` / `useLocation()` хранит текущую позицию, статус и повтор запуска.
  Экраны не создают дополнительные GPS-подписки.
- `ProximityProvider` хранит менеджер зон между переходами и предоставляет ошибки/повтор уведомлений.

Экраны обращаются к данным через Context; SQL остаётся в `database/`. После изменений
и при возвращении на экран кэш перечитывается. Повтор после успешного INSERT, но
неудачного обновления/очистки, не повторяет сам INSERT. Диагностические сообщения
сервисов выводятся только в режиме разработки (`__DEV__`).

Обработаны ошибки открытия БД, запросов, ограничений и транзакций, выбор/загрузка фото,
отказ в разрешениях, выключенная геолокация и сбои уведомлений. Некорректный или отсутствующий
ID метки даёт сообщение и возврат к карте. Отмена выбора фото не меняет данные.

Карта использует `loadingEnabled` и `onMapReady`; после 15 секунд ожидания можно повторить
инициализацию. ErrorBoundary обрабатывает ошибки рендера. Общего `onError` у установленного
MapView нет, а готовность компонента не гарантирует загрузку всех тайлов.

## Хранение фотографий

Системный picker выбирает одно изображение без редактирования. Для этого режима полный
доступ к медиатеке не запрашивается. Камера и микрофон не используются.

До открытия галереи `services/imagePicker.ts` сохраняет запрос и ID исходной метки
через `database/imagePicker.ts`. При запуске Android проверяется `getPendingResultAsync()`.
Результат записывается только в исходную метку; результат без запроса или для удалённой
метки отбрасывается. URI выбранного источника сохраняется до копирования, чтобы повторить
операцию после ошибки. INSERT фото и удаление запроса выполняются в одной транзакции.
Повтор операции не открывает галерею заново и не дублирует сохранённое фото. Если временный
источник уже недоступен, на экране запуска можно пропустить восстановление и выбрать фото заново.

Фото копируется с уникальным именем в `Paths.document/marker-photos/`. Приложение ожидает
завершения асинхронного копирования, проверяет наличие и непустой размер файла, затем
записывает в SQLite относительный путь `marker-photos/имя-файла`. При отображении URI
строится от текущего `Paths.document`, поэтому смена корня контейнера не ломает ссылки.
При ошибке INSERT новая копия удаляется; при ошибке копирования запись не создаётся.

При удалении сначала меняется БД, затем удаляются собственные копии, на которые больше
нет ссылок. Оригиналы галереи и чужие файлы не затрагиваются. Общей транзакции между SQLite
и файловой системой нет: неудачная очистка показывает ошибку и повторяется при следующей
успешной синхронизации/запуске. Проверка выполняется только после чтения всех путей из БД;
сравниваются относительные пути, включая распознанные URI прежнего контейнера.
Если файл недоступен, вместо миниатюры показывается ошибка с повтором загрузки.

## Геолокация и уведомления

Запрашивается только разрешение местоположения при использовании приложения.
Единственный `watchPositionAsync` использует `Accuracy.High`, `timeInterval: 5000`
и `distanceInterval: 5`. Временной интервал применяется на Android; ОС не гарантирует
получение координат строго каждые 5 секунд или 5 метров.

При уходе в фон/неактивное состояние watch и таймеры снимаются; при возвращении
запускаются заново. Поздно завершившийся запуск подписки также корректно очищается.
Отображаются ожидание первой позиции, отказ, отключённые службы и ошибки.
Без разрешения на GPS карта, сохранённые метки и фотографии остаются доступны.

`calculateDistance` использует формулу Хаверсина и возвращает метры.
В `services/proximity.ts` вход задан как `PROXIMITY_THRESHOLD = 100`, выход —
`PROXIMITY_EXIT_THRESHOLD = 150`. Промежуток между границами не меняет текущее посещение.
Для пересчёта принимаются только корректные координаты с точностью не хуже 50 м,
возрастом до 30 секунд и временем не более чем на 5 секунд в будущем.
Координаты или список меток изменились — зоны пересчитываются:

1. При расстоянии **≤ 100 м** отправляется «Вы рядом с меткой!» с ID маркера.
2. `Map` по `markerId` хранит `notificationId` и `timestamp`. Пока метка в зоне, повторов нет.
3. `Set` выполняющихся отправок блокирует дубли до завершения асинхронного вызова.
4. При расстоянии **> 150 м** или удалении метки состояние очищается, уведомление удаляется.
   Поздний результат отправки для уже покинутой зоны также удаляется.
5. При повторном входе разрешена новая отправка. Если старое уведомление не удалось
   удалить, новое для этой метки ждёт успешной очистки. Остальные метки независимы.
6. После ошибки возможен повтор по следующему обновлению координат/меток или кнопке;
   немедленного бесконечного цикла повторов нет.

Отсутствие, плохая точность или истёкший срок позиции не считаются выходом из зоны: состояние сохраняется до новой позиции,
но новые отправки не запускаются. Удалённые маркеры очищаются и без GPS.

`services/notifications.ts` создаёт Android-канал до запроса разрешения, регистрирует
общий `setNotificationHandler` для показа при открытом приложении. Успех `scheduleNotificationAsync`
сам по себе не означает успешный показ: сервис ждёт `handleSuccess` или `handleError`.
Если за 5 секунд callback не получен (например, приложение ушло в фон), проверяется список
показанных уведомлений. Ошибка освобождает метку для повтора после очистки неудачной отправки.
Подтверждение обработчика не гарантирует, что пользователь увидел баннер: на это влияют настройки ОС.

При новом запуске менеджер сначала читает запланированные и показанные системные уведомления.
Он распознаёт собственный `scope` и точный формат сообщений старой версии, восстанавливает
показанные ID, удаляет дубли, устаревшие запросы и уведомления удалённых меток.
Пока сверка не завершена, новые отправки заблокированы. При ошибке доступен повтор.
Удаление затрагивает конкретный ID (отмена ожидающего + удаление показанного), чужие уведомления пропускаются.
После отказа системный запрос автоматически не повторяется; можно открыть настройки.
Это локальные уведомления без push-токенов и сервера. Временная тестовая кнопка удалена.

### Карта, фото и сохранение данных — вручную

1. Добавьте две метки долгими нажатиями. Откройте каждую, проверьте ID/координаты и возврат.
2. Первой добавьте два фото, второй — одно. Отмените ещё один выбор: ничего не добавилось.
   Списки должны быть раздельными; быстрые повторные нажатия не дублируют выбор.
3. Полностью закройте Expo Go, не очищая данные, и откройте тот же проект: метки и фото остались.
4. Удалите фото, перезапустите: оно не возвращается. Удаление метки сначала отмените,
   затем подтвердите: вернитесь на карту, метка исчезла, данные второй метки сохранились.
5. Проверьте неверный и отсутствующий ID через deep link Expo Go. Возьмите адрес Metro,
   добавьте `/--/marker/abc`, `/--/marker/0` или `/--/marker/999999999`.
   Пример команды для Android (подставьте адрес из терминала):

```sh
npx uri-scheme open "exp://АДРЕС-И-ПОРТ-METRO/--/marker/abc" --android
```

Схему можно дополнительно проверить на соединении БД: `PRAGMA user_version` должен
вернуть 3, `PRAGMA foreign_keys` — 1; `PRAGMA foreign_key_check` — пустой результат.
После удаления метки в `marker_images` не должно остаться строк с её `marker_id`.

На Android включите **Настройки разработчика → Не сохранять действия (Don't keep activities)**,
откройте галерею у второй из двух меток и выберите фото. После восстановления приложения
оно должно появиться только у второй метки, в одном экземпляре. Проверьте также отмену выбора.
По окончании выключите настройку. Механизм описан в [Expo ImagePicker](https://docs.expo.dev/versions/latest/sdk/imagepicker/#imagepickergetpendingresultasync).

### GPS и уведомления — Android Emulator

1. Запустите AVD с Google Play через Android Studio Device Manager и `npm run android`.
   Разрешите геолокацию при использовании приложения.
2. **More (…) → Location → Single points**: найдите `56.8389, 60.6057`, выберите точку,
   нажмите **Set location**, дождитесь координат в приложении.
3. Добавьте две метки в 20–50 метрах от синей точки. Разрешите уведомления — по одному для каждой.
4. Установите `56.8391, 60.6057`: оставаясь возле меток, проверьте отсутствие дублей,
   в том числе после переходов на детали и обратно.
5. Установите `56.8439, 60.6057` (примерно 550 м севернее): после обновления GPS
   уведомления должны исчезнуть. Вернитесь в исходную точку — появятся снова.
6. Удалите одну близкую метку: исчезнет только её уведомление.
7. Для движения по маршруту используйте **Routes → Save route**, выберите сохранённый
   маршрут и нажмите **Play route**; остановка — **Stop route**.

Некоторые controls доступны только в отдельном окне эмулятора.
Названия сверены с [документацией Android Emulator](https://developer.android.com/studio/run/emulator-extended-controls).

### Дополнительно на физическом устройстве

- Откажите в GPS/уведомлениях, затем разрешите их через настройки Expo Go. Карта и фото
  работают при отказе; после разрешения можно повторить операцию.
- Выключите службы геолокации телефона: должно появиться сообщение; включите и повторите.
- Пройдите внутрь/наружу зоны с запасом (например, 30 и 200 м), затем около границы.
- Последовательность 99 → 101 → 99 м не должна создавать повтор; выход за 150 м и
  следующий вход в 100 м должны разрешить новый показ. При неточной позиции уведомлений нет.
- Сверните приложение, переместитесь и вернитесь: проверка возобновится по свежей позиции.
- Проверьте системную галерею, баннеры/звук, полное закрытие и перезагрузку устройства.
  После перезагрузки откройте тот же проект с доступным Metro: данные должны сохраниться,
  уже показанное уведомление должно восстановиться без дубля. Выход за 150 м или удаление
  метки должны убрать уведомление прошлого запуска. Если пользователь сам убрал уведомление
  из системного списка, новый запуск может уведомить снова.
