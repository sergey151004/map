# Карта и метки

Учебное приложение на React Native, Expo SDK 57, TypeScript и Expo Router.
Выполнено задание 1 и подключена SQLite из задания 2. Задание 3 пока не реализовано.
Исходные задания находятся в `tasks/`.

## Установка и запуск

Требуются Node.js 24 LTS, npm и Expo Go с поддержкой SDK 57.

```powershell
cd D:\coding\map_project
npm ci
npm start
```

Подключите компьютер и телефон к одной сети Wi-Fi. Отсканируйте QR-код:
на Android — в Expo Go, на iPhone — камерой. Для Android-эмулятора есть
`npm run android`; iOS-симулятор требует macOS.
Если сеть блокирует подключение, используйте `npx expo start --go --tunnel`
(Expo может предложить установить `@expo/ngrok`).

На этой машине диск C: заполнен. Кеш npm перенаправлен в `.npm-cache/` через `.npmrc`.
Если Expo сообщает `ENOSPC`, перед запуском в текущем PowerShell выполните:

```powershell
$env:__UNSAFE_EXPO_HOME_DIRECTORY = 'D:\coding\map_project\.expo-cache'
npm start
```

Новая служебная папка Expo не использует сохранённый в прежней папке вход в аккаунт.
Кеши, `node_modules`, `.expo` и `dist` исключены из Git.

Зависимости подбирались через `npx expo install`, в том числе:

```powershell
npx expo install react-native-maps expo-image-picker expo-sqlite expo-file-system
```

Установлены Expo 57.0.27, SQLite 57.0.4 и FileSystem 57.0.7.
Для обычной повторной установки используйте `npm ci`, чтобы сохранить версии из lock-файла.

## Как работает приложение

- Долгое нажатие на карту добавляет маркер в SQLite.
- Нажатие на маркер открывает его числовой ID, координаты и фотографии.
- Системная галерея выбирает одну фотографию. Отмена не изменяет данные.
- Выбранный файл копируется в `Paths.document/marker-photos/` с уникальным именем.
  В SQLite сохраняется URI копии, а не временный URI галереи.
- Фотографии можно удалять по одной. Удаление маркера требует подтверждения,
  удаляет связанные записи и копии фото, затем возвращает на карту.
- Данные обновляются после операций и при возврате на экран через `useFocusEffect`.
- Загрузка, ошибка и кнопка повтора видны на экране. Ошибку можно закрыть,
  например чтобы выбрать другое фото вместо недоступного исходного файла.
- После полного закрытия и открытия приложения маркеры и фотографии сохраняются.
  Удаление приложения или очистка его данных удалит и локальные данные.

## Соединение, Context и ошибки

`DatabaseProvider` находится над навигатором в `app/_layout.tsx`.
`useDatabase()` предоставляет шесть операций задания, `markers`, `images`,
`isLoading`, `error`, обновление и повтор. Массивы в Context — кэш содержимого SQLite,
а не отдельное хранилище. Старый `MarkersContext` удалён.

`database/connection.ts` управляет одним соединением. Инициализация, операции,
синхронизация и файловая очистка выполняются последовательно. Обычная навигация
соединение не закрывает. При размонтировании провайдера закрытие ставится в очередь
после уже принятых запросов. Повторная установка эффекта в React Strict Mode также
проходит через эту очередь, не создавая два одновременно открытых соединения.

Если основной запрос уже выполнен, но чтение результата или очистка файлов не удались,
кнопка повтора выполняет только оставшиеся шаги: успешный INSERT не повторяется.
После закрытия сообщения данные перечитываются без повторения отменённой операции.
Диагностика выводится только при `__DEV__`; исходная причина ошибки сохраняется в `cause`.

## SQLite

SQL находится только в `database/`. Используются актуальные асинхронные методы
`expo-sqlite` и встроенный тип `SQLiteDatabase`, без ORM и `@types/sqlite3`.

`initDatabase()` открывает `markers.db` в постоянной папке SQLite приложения.
До транзакций включается и проверяется `PRAGMA foreign_keys = ON`.
При `PRAGMA user_version = 0` обе таблицы создаются вместе с установкой версии 1
в одной транзакции. Повторная инициализация сохраняет данные. Более новая или
некорректная версия, конфликт схемы и ошибки запросов не приводят к сбросу базы.

```sql
CREATE TABLE markers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    latitude REAL NOT NULL,
    longitude REAL NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE marker_images (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    marker_id INTEGER NOT NULL,
    uri TEXT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (marker_id) REFERENCES markers (id) ON DELETE CASCADE
);
```

Операции: `addMarker`, `deleteMarker`, `getMarkers`, `addImage`, `deleteImage`,
`getMarkerImages`; внутренний `getAllImages` нужен для синхронизации и очистки файлов.
Слой SQL принимает первым параметром соединение, а Context скрывает его от экранов.
Значения передаются через `?`. Один DELETE и его каскад атомарны в SQLite.
В результатах `marker_id` отображается в `markerId`, `created_at` — в `createdAt`;
названия столбцов в БД не меняются. `createdAt` допускает NULL, как схема задания.

## Согласованность фотографий и базы

Файловая система и SQLite не имеют общей транзакции. Поэтому используется такой порядок:

1. Создать копию фото и проверить её наличие и непустой размер.
2. Записать URI копии в БД. При ошибке записи удалить новую копию.
3. При удалении сначала выполнить SQL, затем убрать принадлежащие приложению файлы,
   которые больше не упоминаются ни в одной записи изображений.

Если SQL-удаление не удалось, файлы остаются целыми. Если очистка файла не удалась,
запись уже удалена, но остаётся копия: показывается ошибка и доступен повтор очистки.
Такая же проверка выполняется при запуске и синхронизации. Она убирает незавершённые
копии после остановки процесса между копированием и INSERT или между DELETE и очисткой.
Сканирование выполняется только после успешного чтения всех URI из БД и в той же очереди,
поэтому не удаляет файл незавершённой операции добавления.

Удаляются только файлы с нашими именами `photo-...` непосредственно в `marker-photos`.
Оригиналы галереи, другие каталоги и чужие файлы не удаляются. Неизвестные URI из старой
базы не считаются принадлежащими приложению. Произвольная очистка документов или удаление
пользователем файлов вручную всё ещё может сделать фотографию недоступной: миниатюра
покажет ошибку с возможностью повтора или удаления записи.

## Проверки

```powershell
npm run typecheck
npm run test:storage
npx expo install --check
npx expo-doctor
npx expo export --platform all
```

`test:storage` проверяет настоящий SQL на SQLite из Node.js и файловые сервисы через
адаптер к временным файлам. Проверяются схема, CRUD, каскад, сохранение после повторного
открытия, откат ошибок, очередь и закрытие соединения, повтор без дубликата, компенсация
ошибок копирования/INSERT, повторная очистка и сохранность оригиналов.
`npm run test:database` запускает только проверки базы и очереди.
Эти тесты не заменяют запуск нативного моста Expo и интерфейса на устройстве.
Телефон и эмулятор в рабочей среде недоступны.

Для этого этапа прошли TypeScript, 11 тестов хранилища, все 21 проверки Expo Doctor
и экспорт Android/iOS. Поведение нативного picker и перезапуск Expo Go нужно проверить вручную.

### Ручная проверка сохранения

1. Запустите приложение в Expo Go. Дождитесь карты и добавьте две метки долгими нажатиями.
2. Откройте первую: проверьте ID/координаты, добавьте два разных фото. Второй добавьте одно.
3. Вернитесь на карту и снова откройте обе метки. Списки фото должны быть раздельными.
4. Полностью закройте Expo Go через список приложений (на Android можно принудительно
   остановить его в настройках). Не очищайте данные приложения и не переустанавливайте его.
5. Снова откройте тот же проект через Expo Go: оба маркера и все три миниатюры должны остаться.
6. Удалите одну фотографию первой метки и повторите полное закрытие/открытие:
   удалённая фотография не возвращается, остальные остаются.
7. На первой метке нажмите «Удалить маркер», сначала отмените: всё остаётся.
   Затем подтвердите: откроется карта, первая метка исчезнет, вторая останется.
8. Перезапустите ещё раз: удалённая метка не возвращается, фото второй доступны.
9. Проверьте отмену галереи и быстрые повторные нажатия: одна операция не должна добавлять дубликаты.
10. Проверьте неверную ссылку `exp://<адрес Metro>/--/marker/abc` и несуществующий ID:
    должно быть понятное сообщение с возвратом на карту.

Схему можно дополнительно осмотреть через `PRAGMA table_info(markers)`,
`PRAGMA table_info(marker_images)`, `PRAGMA foreign_key_list(marker_images)` на том же
соединении в отладчике. `foreign_keys` и `user_version` должны быть 1,
`foreign_key_check` — пустым. После удаления маркера запрос
`SELECT * FROM marker_images WHERE marker_id = ?` для его ID должен вернуть пустой список.
Папка `Paths.document/marker-photos` должна содержать только используемые копии
после успешной очистки. Полный каскад и откат при его ошибке также проверяются тестами.

Для проверки ошибок на устройстве можно временно вызвать исключение перед копированием,
перед INSERT или перед удалением файла в соответствующем сервисе. После восстановления
кода нажмите «Повторить операцию»: не должно появиться лишней записи. После неудачного
копирования/INSERT не должно быть новой строки, после ошибки очистки — чужих удалённых файлов.

## Карта и разрешения

`react-native-maps` 1.27.2 использует `onMapReady` и `loadingEnabled`. После 15 секунд
ожидания готовности появляется повтор инициализации. Общего `onError` карта не предоставляет;
готовность не гарантирует загрузку всех тайлов. ErrorBoundary ловит ошибки рендера React,
но не нативные сбои. `onMapLoaded` не используется из-за отсутствия поддержки Apple Maps.

В Expo Go для карт не нужны дополнительные ключи. Галерея выбирает только фотографии
без редактирования: системный picker на поддерживаемых Android/iOS не требует полного
доступа к медиатеке. Камера и микрофон не используются. Отмена обрабатывается отдельно,
ошибки доступа и чтения показываются на экране. Копирование в документы приложения
не требует разрешения на общую файловую систему телефона.

## Основные файлы

- `app/` — карта, детали и навигация.
- `contexts/DatabaseContext.tsx` — соединение, операции, кэш и повтор ошибок.
- `database/` — схема, SQL, очередь соединения и ошибки базы.
- `services/` — сохранение/очистка копий и повтор без дубликатов.
- `components/ImageList.tsx`, `components/DatabaseStatus.tsx` — фото и состояние операций.
- `types.ts`, `utils/parseMarkerId.ts` — модели и проверка ID маршрута.
- `tests/` — автоматические проверки хранилища.
